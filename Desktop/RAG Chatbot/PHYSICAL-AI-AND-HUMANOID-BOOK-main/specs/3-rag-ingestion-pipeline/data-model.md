# Data Model: Document Chunk

This document defines the data structure for a "Document Chunk" as it will be stored in the Qdrant vector database.

## 1. Entity: DocumentChunk

A `DocumentChunk` represents a single piece of text extracted from the book, along with its vector embedding and associated metadata.

### 2. Schema

The data for each point in the Qdrant collection will consist of a vector and a payload.

- **Vector**: The high-dimensional embedding generated by Cohere's `embed-english-v3.0` model.
- **Payload**: A JSON object containing the metadata and the original text.

#### Payload Fields

| Field Name     | Type   | Description                                                                                                   | Example                                   |
|----------------|--------|---------------------------------------------------------------------------------------------------------------|-------------------------------------------|
| `text`         | string | The actual text content of the chunk.                                                                         | "Docusaurus is a static-site generator."  |
| `url`          | string | The full URL of the source page from which the text was extracted.                                              | `https://my-book.github.io/docs/intro`    |
| `page_title`   | string | The title of the source page, typically extracted from the `<title>` or `<h1>` HTML tag.                       | "Introduction"                            |
| `chunk_index`  | integer| The sequential index of the chunk within the source page.                                                       | 3                                         |

### 3. Qdrant Collection

- **Collection Name**: `physical_ai_humanoid_book`
- **Vector Size**: `1024` (corresponding to Cohere's `embed-english-v3.0`)
- **Distance Metric**: `Cosine` (recommended for sentence-transformer models like Cohere's)

### 4. State Transitions
- This is an immutable data model for the purpose of this pipeline. Chunks are created and stored. If the source content changes, the pipeline is expected to re-generate and overwrite the existing chunks for that page during an update run.
