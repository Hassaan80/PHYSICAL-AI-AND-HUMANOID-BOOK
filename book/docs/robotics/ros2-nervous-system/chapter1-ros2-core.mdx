# ROS 2 Communication Core: Nodes, Topics, Services, DDS

This chapter introduces fundamental ROS 2 communication concepts—nodes, topics, services, and the underlying Data Distribution Service (DDS)—essential for real-time control and interaction in humanoid robots.

## ROS 2 Nodes and their Lifecycle

**Nodes** are executable processes encapsulating specific robotic functionalities like sensor reading, data processing, or control. This modularity allows independent development, distributed computation, and easy component swapping.

### Node Communication and Modularity

Nodes communicate using ROS 2 mechanisms (topics, services, actions), forming a distributed graph. This promotes reusability and flexible system design.

### ROS 2 Node Lifecycle

ROS 2 features a **managed lifecycle** for predictable node operation, crucial for robust systems. Standard states include: **Unconfigured**, **Inactive**, **Active**, and **Finalized**. Explicit commands manage transitions, offering controlled, fault-tolerant system management, especially for humanoid robot components.

## ROS 2 Topics: Asynchronous Data Streaming

**Topics** enable asynchronous, many-to-many communication for continuous data streams like sensor data, robot state, or frequent control commands.

### Publishers and Subscribers

*   **Publishers**: Nodes sending data of a specific message type to a named topic.
*   **Subscribers**: Nodes receiving messages published on a topic.

This decoupled model ensures nodes agree on topic name and message type, without needing direct knowledge of each other.

### Message Types

**Message types** define the structured data exchanged over topics (e.g., `std_msgs/msg/String`, `geometry_msgs/msg/Twist`). This ensures well-defined and parsable data, vital for humanoid sensor data, robot state, and low-level commands.

## ROS 2 Services: Synchronous Request/Response Communication

**Services** provide a synchronous request/response model, ideal when a node needs specific information or to trigger an action and await a response.

### Clients and Servers

*   **Service Server**: Offers a service, defining its type and registering under a name. Executes a callback and sends a response when called.
*   **Service Client**: Requests a service and waits for a response.

Services are suitable for tasks like querying information, triggering actions, or configuring nodes, and for humanoids, complex motion initiation, system status checks, or environment interaction.

## The Role of DDS (Data Distribution Service) in ROS 2 Communication

**DDS (Data Distribution Service)** underlies all ROS 2 communication, providing an open standard for real-time, publish-subscribe, peer-to-peer data exchange, optimized for mission-critical systems.

### Key Features of DDS Relevant to ROS 2

1.  **Decentralized Architecture**: Nodes discover and communicate directly, eliminating single points of failure and improving scalability.
2.  **Quality of Service (QoS) Policies**: Fine-tunes communication (reliability, durability, liveliness, history) for different data types, crucial for robotics.
3.  **Real-time Performance**: Optimized for low-latency data exchange.
4.  **Language and Platform Agnostic**: Enables interoperability across diverse system components.

DDS abstracts network complexities, allowing roboticists to focus on functionality, especially beneficial for complex humanoid systems.

## Simple ROS 2 Publisher-Subscriber Example (Python)

To illustrate topics, publishers, and subscribers:

### 1. Publisher Node (`simple_publisher.py`)

```python
import rclpy
from rclpy.node import Node
from std_msgs.msg import String

class SimplePublisher(Node):
    def __init__(self):
        super().__init__('simple_publisher')
        self.publisher_ = self.create_publisher(String, 'my_topic', 10)
        self.timer = self.create_timer(0.5, self.timer_callback)
        self.i = 0
    def timer_callback(self):
        msg = String()
        msg.data = f'Hello ROS 2: {self.i}'
        self.publisher_.publish(msg)
        self.get_logger().info(f'Publishing: "{msg.data}"')
        self.i += 1
def main(args=None):
    rclpy.init(args=args); node = SimplePublisher(); rclpy.spin(node); node.destroy_node(); rclpy.shutdown()
if __name__ == '__main__': main()
```

### 2. Subscriber Node (`simple_subscriber.py`)

```python
import rclpy
from rclpy.node import Node
from std_msgs.msg import String

class SimpleSubscriber(Node):
    def __init__(self):
        super().__init__('simple_subscriber')
        self.subscription = self.create_subscription(String, 'my_topic', self.listener_callback, 10)
        self.subscription # prevent unused variable warning
    def listener_callback(self, msg):
        self.get_logger().info(f'I heard: "{msg.data}"')
def main(args=None):
    rclpy.init(args=args); node = SimpleSubscriber(); rclpy.spin(node); node.destroy_node(); rclpy.shutdown()
if __name__ == '__main__': main()
```

### 3. How to Run

1.  Save publisher/subscriber code in your ROS 2 package's `src` directory.
2.  Build your ROS 2 package.
3.  In two terminals, run: `ros2 run your_package_name simple_publisher` and `ros2 run your_package_name simple_subscriber`.

## Simple ROS 2 Service-Client Example (Python)

Demonstrates request/response communication with a server adding two integers and a client requesting addition.

### 1. Service Server Node (`simple_service_server.py`)

`srv/AddTwoInts.srv`:
```
int64 a
int64 b
---
int64 sum
```
Server code:
```python
import rclpy
from rclpy.node import Node
from example_interfaces.srv import AddTwoInts

class SimpleServiceServer(Node):
    def __init__(self):
        super().__init__('simple_service_server'); self.srv = self.create_service(AddTwoInts, 'add_two_ints', self.add_two_ints_callback)
        self.get_logger().info('Add Two Ints Service Server ready.')
    def add_two_ints_callback(self, request, response):
        response.sum = request.a + request.b; self.get_logger().info(f'Incoming request: a={request.a}, b={request.b}. Sending response: sum={response.sum}')
        return response
def main(args=None):
    rclpy.init(args=args); node = SimpleServiceServer(); rclpy.spin(node); rclpy.shutdown()
if __name__ == '__main__': main()
```

### 2. Service Client Node (`simple_service_client.py`)

```python
import rclpy
from rclpy.node import Node
from example_interfaces.srv import AddTwoInts; import sys

class SimpleServiceClient(Node):
    def __init__(self):
        super().__init__('simple_service_client'); self.client = self.create_client(AddTwoInts, 'add_two_ints')
        while not self.client.wait_for_service(timeout_sec=1.0): self.get_logger().info('service not available, waiting...')
        self.req = AddTwoInts.Request()
    def send_request(self, a, b):
        self.req.a = a; self.req.b = b; self.future = self.client.call_async(self.req)
        rclpy.spin_until_future_complete(self, self.future); return self.future.result()

def main(args=None):
    rclpy.init(args=args)
    if len(sys.argv) != 3: print('Usage: ros2 run your_package_name simple_service_client A B'); rclpy.shutdown(); sys.exit(1)
    client_node = SimpleServiceClient(); a = int(sys.argv[1]); b = int(sys.argv[2])
    response = client_node.send_request(a, b); client_node.get_logger().info(f'Result of add_two_ints: for {a} + {b} = {response.sum}')
    client_node.destroy_node(); rclpy.shutdown()
if __name__ == '__main__': main()
```

### 3. How to Run

1.  Define `AddTwoInts.srv` and place Python nodes in your ROS 2 package's `src`.
2.  Build your ROS 2 package.
3.  In two terminals, run: `ros2 run your_package_name simple_service_server` and `ros2 run your_package_name simple_service_client 5 7`.
